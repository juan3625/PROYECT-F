# Product Backlog de FINDRIX

## Alcance

FINDRIX es una aplicación web de finanzas personales construida con React/Vite en el frontend, Node.js/Express en el backend y PostgreSQL como base de datos. El backlog cubre registro e inicio de sesión, movimientos financieros, categorías, metas, préstamos, economía `cash-first`, reportes, preferencias y despliegue.

Los criterios de aceptación son verificables. La autenticación aparece porque forma parte del alcance real de FINDRIX; su funcionamiento en producción permanece pendiente de validación.

| PBI | Historia de Usuario | Criterios de Aceptación |
|---|---|---|
| PBI001 | Como visitante, quiero crear una cuenta con nombre, correo y contraseña, para comenzar a usar FINDRIX. | 1. Se validan nombre, correo y contraseña antes de enviar. 2. Una contraseña menor de 8 caracteres es rechazada. 3. Un correo inválido muestra un mensaje claro. 4. Un correo existente no crea un duplicado. 5. Una cuenta válida se persiste y devuelve una respuesta controlada. |
| PBI002 | Como usuario registrado, quiero iniciar sesión, para acceder de forma segura a mis finanzas. | 1. El sistema acepta credenciales válidas. 2. Credenciales inválidas no permiten el acceso. 3. La sesión recibe un token o estado equivalente. 4. Las rutas protegidas requieren sesión. 5. El usuario recibe un mensaje comprensible ante un error del servidor. |
| PBI003 | Como usuario, quiero cerrar sesión, para terminar mi acceso en el dispositivo. | 1. La sesión se elimina del estado del frontend. 2. El usuario vuelve a la pantalla de acceso. 3. Una ruta protegida no queda accesible después del cierre. |
| PBI004 | Como usuario, quiero registrar un gasto, para conocer en qué utilizo mi dinero. | 1. Se solicitan los campos obligatorios. 2. El valor debe ser numérico y positivo. 3. Se puede asociar una categoría y una fecha. 4. El gasto aparece en movimientos y resumen después de guardarse. |
| PBI005 | Como usuario, quiero registrar un ingreso, para conocer el dinero que recibo. | 1. Se valida el valor. 2. Se registra fecha y descripción. 3. El ingreso aparece en movimientos. 4. El resumen actualiza sus totales. |
| PBI006 | Como usuario, quiero consultar y filtrar movimientos, para analizar mis gastos e ingresos. | 1. Se muestran los movimientos del usuario autenticado. 2. Se puede filtrar por tipo, categoría o periodo cuando corresponda. 3. Un resultado vacío comunica que no hay coincidencias. 4. Los datos de otro usuario no aparecen. |
| PBI007 | Como usuario, quiero crear y administrar categorías, para clasificar mis operaciones. | 1. El nombre de categoría es obligatorio. 2. Se pueden crear y editar categorías propias. 3. No se permite un nombre inválido o vacío. 4. Una categoría usada por movimientos no se elimina sin una respuesta controlada. |
| PBI008 | Como usuario, quiero crear metas de ahorro y registrar abonos, para controlar mi progreso. | 1. La meta requiere nombre y objetivo válido. 2. Un abono positivo actualiza el progreso. 3. El porcentaje no supera el 100 %. 4. La meta se muestra con su avance actualizado. |
| PBI009 | Como usuario, quiero registrar préstamos y pagos, para llevar control de mis obligaciones. | 1. Se registran los datos mínimos del préstamo. 2. Un pago positivo reduce el saldo pendiente. 3. El sistema evita saldos negativos no permitidos. 4. El estado del préstamo se actualiza al completar el saldo. |
| PBI010 | Como usuario, quiero registrar efectivo, propinas y trabajos extras, para representar mi economía cotidiana. | 1. Se puede registrar una entrada de efectivo. 2. Se identifica el origen o descripción. 3. El saldo de caja chica se recalcula. 4. El movimiento aparece en la vista de economía. |
| PBI011 | Como usuario, quiero consultar resúmenes y gráficas, para comprender mi comportamiento financiero. | 1. Las gráficas usan los movimientos disponibles. 2. Los totales coinciden con los datos consultados. 3. Los estados sin información no muestran gráficas engañosas. 4. Los periodos se presentan de forma comprensible. |
| PBI012 | Como usuario, quiero personalizar tema, color y tamaño de texto, para adaptar la aplicación a mis preferencias. | 1. Se puede seleccionar tema claro, oscuro o automático. 2. El color de acento se refleja en la interfaz. 3. El tamaño de texto cambia de forma visible. 4. Las preferencias se conservan al recargar cuando corresponda. |
| PBI013 | Como usuario, quiero usar FINDRIX desde móvil o instalarla como PWA, para consultar mis finanzas con facilidad. | 1. La interfaz se adapta a pantallas móviles y de escritorio. 2. El manifest y los íconos están disponibles. 3. La navegación no se desborda horizontalmente. 4. El botón de registro rápido y el zorrito no se superponen. |
| PBI014 | Como responsable del proyecto, quiero desplegar frontend, backend y base de datos con variables separadas, para publicar la aplicación sin exponer secretos. | 1. El frontend utiliza su URL de API configurada. 2. El backend utiliza `DATABASE_URL`, JWT y `FRONTEND_URL` desde el entorno. 3. Los archivos `.env` no se versionan. 4. El despliegue informa errores sin revelar credenciales. |
| PBI015 | Como responsable de calidad, quiero ejecutar pruebas funcionales de autenticación y módulos financieros, para confirmar que la versión publicada funciona. | 1. Existe una matriz de casos y resultados. 2. Registro e inicio de sesión tienen evidencias. 3. Se prueban datos válidos e inválidos. 4. Los defectos se registran con pasos para reproducirlos. 5. No se marca la fase como terminada sin una ejecución exitosa reproducible. |
